# stepwise-explainer

対象を先に読み、聞き手の理解度を聞いてから、段階的な HTML 図解で説明する。対象は問わない（変更差分、コード、文書、仕様、概念、エラーの原因など）。

説明の本体は HTML である。チャットには一文の要約、図に載せられないこと、ファイルのパスだけを書く。

## 1. 対象を読む

質問を対象に合わせるために読む。コードなら該当ファイル、文書なら本文、概念なら構成要素、エラーなら原因まで辿る。変更差分なら差分と説明文の両方を読む。

読みながら次を手元に置く（まだ出さない）。

- 一文の要約
- 説明に必要な用語のリスト
- 対象にある層: 背景（なぜ必要か）、前提になる仕組み、技術的な書き方、影響範囲

完了条件: 原文に当たっていて、要約・用語リスト・対象にある層が手元にある。

## 2. 理解度を聞く

チャット本文に質問を書き、返答を待つ。1回にまとめる。

毎回聞く:

- 説明を聞く目的
- 必要な用語のうち、どれを知っているか（用語は対象から作る）

対象にその層があるときだけ聞く:

- 背景
- 前提になる仕組み
- 技術的な書き方
- 影響範囲

質問の文言と選択肢の形は、層に合わせてその場で決める。

答えが来るまで次へ進まない。一部だけ来たら、来ていない層は厚い側として扱う。「全部分からない」「いいから説明して」なら、目的は全体像、用語はすべて未知として進む。

完了条件: 目的と用語の答えがある。または、全部未知として進む合図を受け取っている。

## 3. 厚みを決める

分かっている層は短く、厚い層（知らない・あいまい・未回答）を長くする。目的に合わせて重点を変える。対象を読んで見つけた食い違いは、図に載せにくければチャット側に残す。

完了条件: 各層が短いか厚いかが決まっている。

## 4. HTML を書く

スキルの読み込み時に提示されるベースディレクトリ（このスキルのフォルダの絶対パス）配下の `assets/player.html` を `/tmp/<対象名>-explainer.html` にコピーする。作業中のリポジトリには書かない。外部のライブラリは足さない。

骨組み（タブ、前へ／次へ、左右キー、色、狭い画面で1列）はそのまま使う。チャットと図解の文言は、ユーザーが使っている言語に合わせる。骨組みの「前へ／次へ」、`html` の `lang`、タブナビの `aria-label` もその言語にする。

`#doc-title` と `<title>` を対象の題にする。`#panels` の中に `section.step` を置く。`data-title` がタブの文言。

- 最初のステップは全体像（一文と、要素のつながり）
- そのあとは厚い層からステップを足す。対象に無い型は作らない
- 仕組みが厚いときは、そのステップに入力を変えると結果が描き直される操作 UI を置く。再描画は入力要素の `oninput` など、その要素に書いた処理で行う
- 比べる必要があるときだけ `.tag-before` / `.tag-after` を使う
- 直すべき点は `.callout-fix`、説明で済む点は `.callout-note`

色と部品のクラスは、コピー元の `assets/player.html` の CSS を正とする。

完了条件: `/tmp` の1ファイルに、全体像と厚い層のステップが入っている。プレースホルダのままの `section` が残っていない。

## 5. チャットに返す

次の3つを書く。

- 一文の要約
- 図に載せられなかったこと（食い違いなど）。無ければ省略する
- HTML のパス

ブラウザでは開かない。表示確認をユーザーに頼まない。

完了条件: パスを伝えていて、ブラウザで開いていない。
