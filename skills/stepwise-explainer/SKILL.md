# stepwise-explainer

対象を先に読み、聞き手の理解度を聞いてから、段階的な HTML 図解で説明する。対象は問わない（変更差分、コード、文書、仕様、概念、エラーの原因など）。

説明の本体は HTML の図と操作 UI である。文はラベルと短い見出しに限る。チャットには一文の要約とファイルのパスだけを書く。

## 1. 対象を読む

質問を対象に合わせるために読む。コードなら該当ファイル、文書なら本文、概念なら構成要素、エラーなら原因まで辿る。変更差分なら差分と説明文の両方を読む。

読みながら次を手元に置く（まだ出さない）。

- 一文の要約
- 説明に必要な用語のリスト
- 対象にある層: 背景（なぜ必要か）、前提になる仕組み、技術的な書き方、影響範囲

完了条件: 原文に当たっていて、要約・用語リスト・対象にある層が手元にある。

## 2. 理解度を聞く

チャット本文に質問を書き、返答を待つ。1回にまとめる。

毎回聞く:

- 説明を聞く目的
- 必要な用語のうち、どれを知っているか（用語は対象から作る）

対象にその層があるときだけ聞く:

- 背景
- 前提になる仕組み
- 技術的な書き方
- 影響範囲

質問の文言と選択肢の形は、層に合わせてその場で決める。

答えが来るまで次へ進まない。一部だけ来たら、来ていない層は厚い側として扱う。「全部分からない」「いいから説明して」なら、目的は全体像、用語はすべて未知として進む。

完了条件: 目的と用語の答えがある。または、全部未知として進む合図を受け取っている。

## 3. 厚みを決める

分かっている層は出さないか、全体像のチップに名前だけ置く。厚い層（知らない・あいまい・未回答）はステップを足し、操作 UI で見せる。文の量は増やさない。目的に合わせて、どの層をステップにするかを変える。対象を読んで見つけた食い違いは、図に載せにくければチャット側に1行で残す。

完了条件: ステップにする層と、出さない層が決まっている。

## 4. HTML を書く

スキルの読み込み時に提示されるベースディレクトリ（このスキルのフォルダの絶対パス）配下の `assets/player.html` をコピーする。書き先は `/tmp/<短い名前>-explainer.html`。短い名前は英数字とハイフンだけにする。作業中のリポジトリには書かない。外部のライブラリは足さない。

骨組み（タブ、前へ／次へ、左右キー、色、狭い画面で1列）はそのまま使う。チャットと図解の文言は、ユーザーが使っている言語に合わせる。骨組みの「前へ／次へ」、`html` の `lang`、タブナビの `aria-label` もその言語にする。

`#doc-title` と `<title>` を対象の題にする。`#doc-lead` にページ全体の一文を入れる。`#panels` の中に `section.step` を置く。`data-title` はタブ用の短い名。各ステップに `h2` を1つ（番号は骨組みが付ける）。

各ステップの中身は次の形にする。

- `h2` の下の `.lead` は1文まで（目安は40字）
- その下は `.lane`（中に `.flow` と `.node`）/ `.demo` / `.rules` / `.callout-fix` / `.callout-note`。仕組みが厚いステップには `.demo` を置く
- 比べるときは `.lane-before` と `.lane-after` を上下に並べ、`.tag-before` / `.tag-after` を付ける
- 図の下の補足は `.caption` 1行まで
- 操作の選択肢は `.pills`、並びの見本は `.row`、番号付きの規則は `.rules`
- 再描画は入力要素の `oninput` など、その要素に書いた処理で行う。結果を出す要素だけを書き換え、入力を含む塊を丸ごと差し替えない
- 最初のステップは全体像。そのあとは厚い層から足す
- 段落で仕組みを書かない

色と部品のクラスは、コピー元の `assets/player.html` の CSS を正とする。

完了条件: 各 `section.step` に `h2` があり、`.lane` / `.demo` / `.rules` / `.callout-fix` / `.callout-note` のどれかがある。`.lead` と `.caption` 以外の `p` が2つ以上あるステップは未完了。`#panels` が空、またはコメントだけの状態で終わっていない。

## 5. チャットに返す

次だけ書く。図解の中身はチャットに写さない。

- 一文の要約
- HTML のパス
- 図に載せられなかった食い違いがあれば、各1行。無ければ省略する

ブラウザでは開かない。表示確認をユーザーに頼まない。

完了条件: パスを伝えていて、チャットに図解の本文が無く、ブラウザで開いていない。
