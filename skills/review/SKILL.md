# レビュー

変更差分をレビューし、バグや改善点があれば指摘する。

## 1. コーディング規約を確認する

指摘に入る前に、リポジトリのコーディング規約を探す。次を順に確認する。

- `CLAUDE.md` / `.claude/rules` / Claude rules 相当のエージェント向け規約
- `AGENTS.md` / `.cursorrules` / `CONTEXT.md` など、他のエージェント・エディタ向け規約
- lint・formatter・型チェックの設定（例: ESLint、Prettier、rubocop、ktlint）
- CONTRIBUTING や docs 内のコーディングガイド

見つかった規約は指摘の根拠にする。規約からの逸脱も指摘対象に含める。

完了条件: 上記の候補を探し終え、存在する規約ファイル・設定を読んでいる（無ければ無いと言えている）。

## 2. 既存実装を参考にする

スタイル・パターン・命名・エラーハンドリングなど「どう書くべきか」に関わる指摘をする前に、同リポジトリの既存の類似実装を読む。差分だけ見て理想論で指摘しない。既存の書き方と整合する提案にする。

完了条件: 指摘候補のうちスタイル・パターンに関わるものについて、比較した既存実装の箇所が言える（該当が無ければその旨が言える）。

## 3. 差分をレビューする

ステップ1の規約とステップ2の既存実装を踏まえ、変更差分のバグ・改善点・規約逸脱を指摘する。

完了条件: 差分を読み終え、指摘の有無を判断している。

## 結果の表示

指摘は次の形式に整形して提示する。

- 指摘がある場合: 深刻度順（High → Medium → Low）に箇条書きにし、各項目は `[深刻度] file:line — 要約 → 提案` の1行で表す。
- 指摘がない場合: 「レビューで問題は見つからなかった」の一行のみで終える。
- 冒頭に指摘件数の一言サマリを添える(例: 「指摘 2件（High 1 / Low 1）」)。
