# 実装

実装作業では `tdd` スキルを使ってテストファーストで進め、コメントを書く・見直すときは `code-comments` スキルを使う。

次のいずれかに当てはまるときは、無理に TDD しない。実装を先に進め、テストは書かないか後回しにする。

- テストを書きづらい実装である
- 既存テストを見て、同種の変更にはテストを書かない方針だと読み取れる

## 1. PR を作る

実装が完了したら、Skill ツールで `pr-create` を発動し、push と PR 作成まで済ませる。

完了条件: PR の URL と base ブランチが分かっている。

## 2. レビューと修正のループ

Skill ツールで `review-loop` を発動し、ステップ1で確定した base ブランチと今回のタスク概要を渡す。周回数は指定せず、`review-loop` の既定に任せる。

完了条件: `review-loop` が終わり、修正した指摘・見送った指摘がそれぞれ分かっている。

## 3. 結果の報告

PR の URL と、`review-loop` の結果（各周の指摘件数・修正した内容・見送った指摘とその理由）を報告する。
