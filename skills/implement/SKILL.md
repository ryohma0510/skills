# 実装

実装作業では `tdd` スキルを使ってテストファーストで進め、コメントを書く・見直すときは `code-comments` スキルを使う。

## 1. PR を作る

実装が完了したら、Skill ツールで `pr-create` を発動し、push と PR 作成まで済ませる。

完了条件: PR の URL と base ブランチが分かっている。

## 2. レビューと修正のループ

次の1周を2回繰り返す。1周目で指摘がゼロでも2周目を回す。

1. Agent ツールでサブエージェントを起動し、`review` スキルを実行させる。プロンプトには、何を実装したか（タスクの概要）と、差分の見方（ステップ1で確定した base ブランチ）を伝える。この後の修正がレビュー結果に依存するため、`run_in_background: false` で起動して完了を待つ。
2. 指摘を鵜呑みにせず、1件ずつ自分で対応すべきかを判断する。該当箇所の差分とその周辺のコードを実際に読み、指摘のとおり壊れている・規約から外れていると確認できたものだけを「確信度が高い」とみなす。
3. 確信度が高い指摘を修正する。確信が持てない指摘は、判断の理由とともに報告に残す。
4. 修正したら、その差分を PR に反映する。コミットして push し、`pr-create` の更新モードで本文を最新の内容に合わせる。

完了条件: 2周を終え、各周のレビュー結果と、修正した指摘・見送った指摘がそれぞれ分かっている。

## 3. 結果の報告

PR の URL と、2周分の指摘件数・修正した内容・見送った指摘とその理由を報告する。
