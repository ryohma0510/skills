## 何をするスキルか

Markdown から装飾文言を削る。判定基準はひとつ。

> その語句を消して、読み手が取る行動が変わるか。変わらなければ装飾。

読み手には人間と Claude の両方が含まれる。SKILL.md やエージェント向け手順書では、
強調しても Claude の従いやすさは上がらない一方、トークンと読む時間は消費される。
「大事だから強調しておく」は、たいてい行動を変えていない。

削るのが仕事で、言い換えは最小限にとどめる。

## いつ使うか

Markdown を新しく書くときは、この判定基準で装飾文言を最初から書かない。
既存ファイルに対して `/doc-trim` で一括に削る使い方もできるが、
それは事後処理であって基準そのものはどちらの場面でも同じ。

## 対象

引数でパスを受け取る（複数可、ディレクトリ可）。

省略された場合は、このセッションで自分が作成・編集した Markdown を対象にする。
それも特定できない場合は対象を尋ねる。カレントディレクトリ配下を勝手に全走査しない。

## 削るもの

### 1. 煽り・脅しの一文

読み手の行動を変えず、危機感だけを足している文。

```diff
- **これを知らないまま作業を始めると必ず的外れなことをする。**
```

手順を読めばやることは変わらない。丸ごと削る。

### 2. 唯一の記述に付いた強調

その文・セルが主張をひとつしか含んでいないなら、強調は何とも対比していない。

```diff
- | `frontend/apps/ui*` | 契約ユーザーが使う実アプリケーション。**こちらが正** |
+ | `frontend/apps/ui*` | 契約ユーザーが使う実アプリケーション。こちらが正 |
- 1. `git status --porcelain` が空でなければ**中断する**。
+ 1. `git status --porcelain` が空でなければ中断する。
```

### 3. 意味を変えない強度副詞

「必ず」「すべて」「絶対に」「決して」「十分に」「確実に」。
頻度や条件を実際に絞っていないなら削る。

```diff
- 採用したパスと、採用しなかった候補を報告に**必ず含める**。
+ 採用したパスと採用しなかった候補を報告に含める。
```

一方、`git diff --exit-code` が「差分ゼロを要求する」のような、
仕様として本当に例外がない記述は残す。事実として厳格なのであって、語気ではない。

### 4. 「〜ではなく〜」の先回り否定

読み手が抱いていない誤解を否定してから本題に入る構文。否定の前半を落とす。

```diff
- これは異常ではなく想定された挙動で、埋めるのが本スキルの仕事。
+ これは想定された挙動で、埋めるのが本スキルの担当範囲。
```

### 5. 禁止の語気

指示として同値なら短いほうを採る。

```diff
- `prototype*` の実装を**手で書き写してはいけない**。
+ `prototype*` の実装は手で書き写さない。
```

ただし「してはいけないこと」を列挙した節の見出しや、
不可逆な操作・データ損失に関わる禁止は語気ごと残す（後述）。

### 6. 直後の再掲・念押し

すぐ上に書いたことを繰り返すだけの一文。

```diff
- 仕組みの詳細は REFERENCE.md に置いてある。**Step 5 で型エラーが出たら必ず読むこと。**
+ 仕組みの詳細は REFERENCE.md にある。Step 5 で型エラーが出たら読む。
```

### 7. 「つまり」「言い換えれば」で始まる同語反復

直前の説明を言い直しただけなら、接続詞ごと削って本文に統合する。

### 8. 解読が要る比喩・レトリック用語

読み手が比喩を解いてから意味を取る語。指している現象を直接書けば同じことが伝わる。

```diff
- ### 4. 否定される藁人形
+ ### 4. 「〜ではなく〜」の先回り否定
- これが手作業パートの正体。
+ これが手作業パート。
```

比喩は消すと文が成立しないため、この分類だけは削除ではなく直接的な記述への置き換えになる。
置き換え後に語数が増えるなら、その比喩は残してよい。

## 残すもの

削りすぎると読み手が判断できなくなる。以下は装飾に見えても残す。

| 残すもの | 理由 |
|---|---|
| 行動を指定する動詞（中断する / 常に実行する / 報告する） | これ自体が指示 |
| 条件・例外・境界（〜が空でなければ、〜が出たら） | 分岐の定義 |
| 理由・根拠（なぜそうするか） | 判断を再現するのに要る。短くしてよいが消さない |
| 技術的事実・数値・パス・コマンド・型名 | 検証可能な情報 |
| 対比のための強調 | 複数の選択肢のうち片方だけが該当することを示す強調は情報を持つ |
| 安全に関わる警告（不可逆操作・データ損失・認証情報） | 語気が抑止として機能している |
| コードブロック・引用ブロック・リンクテキストの中身 | 原文なので触らない |

判断がつかないものは削らずに残し、報告で挙げる。

## 手順

1. 対象ファイルを読む。
2. 上の分類に当てはまる箇所を洗い出す。
3. 削る。削った結果として文がつながらなくなる場合のみ、接続を最小限直す。
   段落構成・見出し・表の構造・文体（ですます / である）は変えない。
4. 削った箇所を分類ごとに報告する。
   - 分類名と件数
   - 判断が分かれたため残したもの（あれば、該当箇所と理由）
5. 意図的に強調したものを消してしまった可能性があるので、
   気になる箇所があれば戻せることを伝える。

## やらないこと

- 文体の統一（ですます ⇔ である の変換）
- 情報の追加・補足の書き足し
- 見出し構成や節の並び替え
- 表を箇条書きにする等の構造変更
- コードブロック内の書き換え

これらが必要だと感じたら、削る作業とは分けてユーザーに提案する。
