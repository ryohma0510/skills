## 何をするスキルか

文章の語彙を、想定読者にとって平易にする。判定基準はひとつ。

> 想定読者が、文脈だけであの語の意味を取れるか。取れない／一瞬ひっかかるなら、同じ意味のより普通の語に置き換える。

自前の「使っていい／ダメ」語彙リストは持たない。根拠は次の公的資料と、本文の「和文で通す」ルールに限定する。

## 根拠（語彙リストを自分で増やさない）

| 役割 | 根拠 |
|---|---|
| 平易さ・専門用語の扱い | 文化庁『[公用文作成の考え方](https://www.bunka.go.jp/seisaku/bunkashingikai/kokugo/hokoku/93657201.html)』（令和4年建議） |
| 分かりにくい外来語 | 国立国語研究所『[「外来語」言い換え提案](https://www2.ninjal.ac.jp/gairaigo/)』 |
| 簡易な技術用語の説明・言い換え | デジタル庁『[重点計画用語集](https://www.digital.go.jp/assets/contents/node/basic_page/field_ref_resources/5ecac8cc-50f1-4168-b989-2bcaabffe870/622c2ad1/20221004_policies_priority_outline_01.pdf)』 |

作業中に判断が根拠に触れるとき、上記を WebFetch / 検索で確認する。
SKILL.md や `references/` に語の可否表を追加しない。

読み手の既定は、母語話者の関係者。外国人向けの「やさしい日本語」は対象外。

## いつ使うか

- ユーザーが分かりにくい語・硬い言い回し・普段使わない言葉・平易化を求めたとき
- AI が書いた文章の語彙を点検するとき
- 新規に文章を書くときも、この基準で最初から書く

## 対象

引数でパスを受け取る（複数可、ディレクトリ可）。

省略された場合は、このセッションで自分が作成・編集した文章ファイルを対象にする。
それも特定できない場合は対象を尋ねる。カレントディレクトリ配下を勝手に全走査しない。

## 直すもの

### 1. 場違いな硬語・漢語

意味は通っても、その文脈の想定読者には高すぎる／場違いな語。

```diff
- 当該機能を実施する。
+ その機能を行う。
```

### 2. 分かりにくい外来語・カタカナ

『「外来語」言い換え提案』にある語は、そこに従う（言い換え、または短い説明）。

```diff
- ソリューションを提供する。
+ 解決策を示す。
```

### 3. 読み手に通じていない技術用語

読み手がエンジニア同士なら、現場で通じる語（API、デプロイ、リポジトリなど）は残す。
非エンジニアや広い読み手向けなら、デジタル庁『重点計画用語集』の分かりやすい表現を優先する。初出だけ短い説明でもよい。

```diff
- API を公開する。
+ API（他のシステムから機能を使うための取り決め）を公開する。
```

### 4. スタイルのための日英混在（ルー大柴調）

**和文で通す。** 日本語の文は日本語の語で書く。英語は、固有名・コード上の識別子・読み手がその語で通じる技術用語に限る。ノリやカッコよさのための英単語挿入はしない。

判定: その英単語を日本語に置き換えても、想定読者の理解が落ちないなら、日本語にする。

```diff
- この feature はとても useful です。Let's 始める。
+ この機能は役に立ちます。始めましょう。
```

## 残すもの

| 残すもの | 理由 |
|---|---|
| 想定読者の現場で通じる技術用語 | 言い換えると却って分かりにくい |
| 固有名・製品名・コード上の識別子 | 原文の指し示す対象 |
| 法令・規格・定訳 | 正確さが優先 |
| ドメインの正式用語で、検索・会話がその語で行われるもの | 共通語彙 |
| コードブロック・引用・リンクテキストの中身 | 原文なので触らない |

判断がつかないものは置き換えず、報告で挙げる。

## 手順

1. 想定読者を一文で決める。明示がなければ「その文書を読む母語話者の関係者」。エンジニア向けと分かれば、現場の技術用語は残す前提にする。
2. 対象ファイルを読む。
3. 上の分類に当てはまる箇所を洗い出す。外来語は言い換え提案、技術用語は重点計画用語集を必要な範囲で確認する。
4. 語の置換と、文がつながらなくなった場合の最小限のつなぎ直しだけ行う。段落構成・見出し・表の構造・文体（ですます / である）は変えない。
5. 変更を報告する。
   - 分類ごとの件数
   - 元 → 先 の代表例
   - 判断が分かれたため残したもの（あれば、該当箇所と理由）

完了条件: 対象全文を読み、直すものに当てはまる箇所を処理している。外来語を直した場合は言い換え提案を、技術用語を直した場合は重点計画用語集を確認している。残したものがあれば理由付きで報告している。

## やらないこと

- 文体の統一（ですます ⇔ である）
- 公用文の表記ルール全般（読点の種類など）への合わせ込み
- 情報の追加・補足の書き足し（初出の短い用語説明を除く）
- 見出し構成や節の並び替え
- コードブロック内の書き換え
- 装飾文言の削除（それは別スキルの担当）
- 会話の名残の削除（それは別スキルの担当）
- 外国人向け「やさしい日本語」（分かち書き・ふりがな等）への変換

これらが必要だと感じたら、語彙の作業とは分けてユーザーに提案する。
