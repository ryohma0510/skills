# area-map

対象のコード領域を **一段上** の抽象で **地図** にする。語彙はプロジェクトのドメイン用語集に合わせる。説明はモジュールの関係と状態に限り、**カテゴリは毎回ちょうど1つ**出す。

## 1. 地図の材料を集める

ユーザーが示した領域（ファイル、ディレクトリ、シンボル、差分）を読む。import・呼び出し・登録箇所を辿り、関連するモジュールと呼び出し元をすべて手元に置く。

ドメイン用語集を探す（glossary、用語集、ユビキタス言語の文書）。あればその語で名付ける。無ければコード上のドメイン名を使い、その場で造語しない。

材料を、聞き手が一度に追える **カテゴリ** に分ける。切り口は対象に合わせる（例: 入口、中核の状態、副作用、呼び出し元）。カテゴリ名も用語集の語にする。各カテゴリについて、登場モジュール・呼び出し元・関係・持つ状態だけを説明用のメモに置く。

完了条件: 用語集の有無が分かっている。関連モジュールと呼び出し元が揃っている。カテゴリが名前付きで分かれている。

## 2. 全体の地図を出す

最初の返答は ASCII アートの全体図から始める。箱と矢印でモジュールと呼び出し元を置き、関係と状態が図から読めるようにする。カテゴリの境界も図に載せる。図の直後に手順 3 へ進む。

完了条件: ASCII の全体図があり、カテゴリの境界が図から読める。

## 3. カテゴリを1つ説明する

最初はユーザーが指した核、または地図の入口（呼び出しの起点）のカテゴリ。以降はユーザーが選んだカテゴリ。

そのカテゴリも、本文の前に ASCII で関係と状態を示す。文は用語集の語で、モジュール同士の関係と状態の遷移だけを書く。コードの詳細（関数の中身、分岐、型、行）は、ユーザーがそのカテゴリで求めたときだけ足す。

完了条件: いま説明したカテゴリはちょうど1つ。ASCII がそのカテゴリの関係と状態を示している。コード詳細はユーザーが求めたときだけ入っている。

## 4. 残りのカテゴリを出す

説明の末尾に、まだ出していないカテゴリを名前で列挙し、どれを続けるかを待つ。残りが無ければ、その旨だけ書く。次のカテゴリ本文は書かない。

完了条件: 未説明のカテゴリが名前で出ている。または残りゼロである旨がある。次のカテゴリ本文は無い。

## 5. 次の返答

ユーザーがカテゴリを選ぶか「次」と言うまで、別カテゴリを足さない。選ばれた1つについて手順 3 と 4 を繰り返す。全体図の描き直しは、関係の理解が変わるときに限る。

完了条件: 選ばれたカテゴリについて手順 3 と 4 を終えている。未選択のカテゴリ本文は増えていない。
